# 日本消費シナリオシミュレータ 設計書

- 作成日: 2026-06-20
- 手法: Superpowers brainstorming スキルに基づく設計フェーズ成果物
- ステータス: ドラフト（ユーザーレビュー待ち）

## 0. 目的（What / Why）

日本の**食品・衣料の消費（前年比 %）**を、いくつかの前提（シナリオ）に基づいて
予測する Web ダッシュボードを構築する。

- **直近3カ月**: バックテストに堪える精度を目標（定量モデル主導）
- **3年後**: 解釈が概ね整合するレベル（トレンド回帰＋広めの不確実性帯、「解釈レベル」と明示）
- **データは必ず出典明示**: 日銀・官庁統計・市場先物を使用し、各系列に出典名・URL・取得日を付与
- **モデルは解釈性重視**: 線形回帰から開始し、段階的に高度化。要因分解を提示

## 1. 利用者と利用形態

- 利用者: アナリスト個人〜少人数共有
- 形態: **Web ダッシュボード（モバイル前提・携帯で確認）**
- シナリオ設定: **プリセット（楽観/ベース/悲観）＋任意ドライバーの手動上書き**

## 2. アーキテクチャ

「重い処理はバッチ、UI は軽量」を基本方針とする。シナリオ計算は線形係数の
適用のみで軽量なため、ブラウザ側（クライアント）で即時計算する。

| レイヤ | 技術 | 役割 |
|---|---|---|
| フロント | **Next.js (App Router) on Vercel** | モバイルレスポンシブなダッシュボード表示。プリセット選択＋手動スライダー |
| シナリオエンジン | クライアント TS/JS | 係数 × ドライバーパスを即時計算（線形・サーバー不要） |
| バッチ | **Python ＋ GitHub Actions（定期）** | API取得 → 整形 → 回帰学習 → 係数・ベースライン・バックテスト結果を JSON 出力 |
| データ受け渡し | リポジトリ内 JSON（出典メタ込み） | Vercel が静的アーティファクトとして読む |

設計上のポイント:

- 重い処理（取得・学習）は GitHub Actions のスケジュール実行でバッチ化し、
  結果 JSON をコミット。Vercel 側は軽量。
- 手動上書きの再計算はブラウザ内で完結 → 携帯でも瞬時・サーバー常駐不要。
- 既存リポジトリ `sme-consult`（Next.js + Vercel）の規約・CI・`vercel.json` 等を流用可能。

```
[GitHub Actions cron]
        |
   [Python ETL] --API--> e-Stat / 日銀 / 市場先物
        |
   [整形・月次パネル] --> DuckDB（再現性・中間生成）
        |
   [OLS 学習 + バックテスト] --> 係数 / ベースライン / 指標を JSON 出力（出典メタ込み）
        |
   （JSON をリポジトリにコミット）
        |
   [Next.js on Vercel] -- 読み込み --> [クライアントのシナリオエンジン] --> 図表表示
```

## 3. データ層（ETL・バッチ）

### 3.1 取得元（API 自動取得）

- **e-Stat（官庁・総務省統計局ほか）**
  - 家計調査（家計収支編）: 食品・被服の消費支出 → 目的変数の素
  - 消費者物価指数（CPI）: 食料・被服の物価
- **日銀 時系列統計データ検索**
  - 政策金利・市場金利、為替（USD/JPY）、短観（消費者・企業マインド代理）
- **市場先物**
  - 食品原材料先物（小麦・大豆・砂糖等）= 食品コストの先行情報
  - 為替先物 / USD/JPY
  - 衣料は国内先物が薄いため、綿（cotton）先物等を代理指標として使用

### 3.2 保存

- **DuckDB**（ファイルベース・再現性が高くバッチ向き）に中間生成物を保存
- 系列ごとに **出典名・出典URL・取得日時・ライセンス/利用条件** をメタとして保存
- 出力テーブル: 生系列 / 月次整合パネル

### 3.3 公表ラグとナウキャスト（重要）

- 家計調査（月次速報）は **翌々月上旬**に公表（例: 2026年4月分 → 2026年6月5日公表、約5〜6週間ラグ）。
- そのため「直近3カ月予測」は、**直近2カ月分の目的変数が未公表**の状態からの予測になる。
- 対応: 公表が早い説明変数（先物・日銀系の速報指標）を先行情報として用い、
  目的変数の欠測期間を**モデルで補完（ナウキャスト）**してから3カ月先を推定する。

出典:
- 家計調査報告（統計局）: https://www.stat.go.jp/data/kakei/sokuhou/tsuki/index.html
- 家計調査 月次（e-Stat）: https://www.e-stat.go.jp/stat-search/files?layout=normal&cycle=1&toukei=00200561&tstat=000000330001&cycle_facet=cycle
- 公表予定一覧（e-Stat リリースカレンダー）: https://www.e-stat.go.jp/release-calendar

## 4. モデル層（バッチ学習）

- **目的変数**: 食品・衣料の前年比 %（カテゴリ別に2モデル）。家計調査ベース（1世帯あたり実質消費の前年比）を初期採用。
- **説明変数（少数・解釈可能）**: 実質賃金/所得、物価（CPI）、金利、消費者心理、
  先物由来の先行コスト、季節性。公表が早い系列を優先。
- **手法**: statsmodels OLS（ラグ付き・先物の先行情報を活用）から開始 → 段階的に高度化。
- **永続化**: 係数・弾力性・要因分解・診断指標・バックテスト指標を、
  モデルバージョン＋データ vintage を付けて JSON 出力。

## 5. シナリオエンジン（クライアント・即時計算）

- 学習済み係数＋最新ベースラインを JSON でロード。
- **プリセット**（楽観/ベース/悲観）が各ドライバーの将来パスを定義。先物がベース期待値の起点。
- 任意ドライバーを**手動上書き** → 係数適用で予測を即時再計算（線形なのでブラウザ内で瞬時）。
- **3カ月**: モデル主導。
- **3年**: トレンド回帰＋広めの信頼区間とし、「解釈レベル」と明示的にラベリング。

## 6. バックテスト

- 3カ月ホライズンを**拡張窓アウトオブサンプル**で評価。
- 指標: MAE / RMSE / 方向的中率を、**ナイーブ基準（前年比 persistence）**と比較。
- 合格ゲート: ホールドアウトでナイーブ基準を上回る（=「それなりにクリア」の定義）。
- 結果はダッシュボードに表示。

## 7. ダッシュボード（Next.js / モバイル前提）

- シナリオ選択（プリセット）＋手動上書きスライダー。
- 図表:
  - 食品・衣料の前年比予測＋不確実性帯
  - 要因分解（各ドライバーの寄与）
  - バックテスト成績パネル
- **出典パネル**: 全系列の出典名・URL・取得日を常時表示。
- モバイルレスポンシブ（単一カラム・タッチ操作前提）。

## 8. リポジトリ構成（予定）

```
etl/          … API取得・整形ジョブ（Python）
models/       … 学習・係数永続化・バックテスト（Python）
data/         … DuckDB・中間生成物（出典メタ付き）
public/data/  … フロントが読む出力JSON（係数・ベースライン・バックテスト・出典）
app/          … Next.js (App Router) ダッシュボード＋クライアントのシナリオエンジン
.github/workflows/ … 定期バッチ（ETL→学習→JSON出力→コミット）
docs/superpowers/specs/ … 本設計書
```

## 9. 前提・未決事項（自己レビュー）

確定済み前提:
1. 目的変数は家計調査ベース（1世帯あたり実質消費の前年比）。POS/商業動態ではない。
2. 衣料の先物は国内が薄いため、綿等の代理指標を使用。
3. UI は Next.js + Vercel。Python バッチは GitHub Actions。
4. `sme-consult` は Next.js + Vercel 構成（規約流用可）。中身は本セッションから未確認のため、流用時に実体確認が必要。

実装計画フェーズで詰めるべき未決事項:
- 使用する e-Stat / 日銀の具体的な統計表 ID・系列コード、API キー取得手順。
- 具体的な先物銘柄とデータ取得先（提供元・利用条件）。
- 説明変数の最終セットとラグ構造、ナウキャストの具体手法。
- バックテストの窓幅・評価期間・合格しきい値の数値。
- プリセット（楽観/ベース/悲観）の各ドライバー設定値の定義方法。
